DAILY USAGE (Copy & Paste)
================================================================================

START THE CHATBOT:
  cd ~/Projects/tally-chatbot
  bash start

STOP THE CHATBOT:
  cd ~/Projects/tally-chatbot
  bash stop

WATCH LOGS:
  tail -f /tmp/tally-proxy.log
  tail -f /tmp/tally-ngrok.log

ACCESS CHATBOT:
  https://tally-chatbot.vercel.app

================================================================================
WHAT HAPPENS WHEN YOU RUN "bash start"
================================================================================

1. Starts proxy server on port 8787
   └─ Reads from TallyPrime on port 9000

2. Starts ngrok tunnel on public domain
   └─ https://headset-slighting-heave.ngrok-free.dev

3. Chatbot becomes accessible
   └─ https://tally-chatbot.vercel.app

Flow: Chatbot UI → Vercel → Tunnel → Local Proxy → TallyPrime

================================================================================
REQUIREMENTS
================================================================================

✓ TallyPrime must be open and accessible on :9000
✓ Python venv at ~/Projects/tally-chatbot/proxy/.venv
✓ ngrok installed at ~/bin/ngrok

If missing any:
  See SETUP_STEPS.md for first-time setup

================================================================================
TROUBLESHOOTING ONE-LINERS
================================================================================

Is TallyPrime running?
  ss -tln | grep 9000

Is proxy running?
  ss -tln | grep 8787

Is ngrok running?
  pgrep ngrok

All services running?
  ss -tln | grep -E '8787|9000' && pgrep ngrok && echo "All good!"

Restart everything:
  bash stop && sleep 2 && bash start

Check proxy errors:
  tail -20 /tmp/tally-proxy.log

Check tunnel errors:
  tail -20 /tmp/tally-ngrok.log

Clear old processes (nuclear option):
  pkill ngrok; pkill -f uvicorn; sleep 2; bash start

WHY THE OLD COMMAND FAILED
================================================================================

You ran:  sh start-local.sh
Error:   "set: Illegal option -o pipefall"

Reason:   Script needs bash, but you used sh (minimal shell)
Fix:      Use "bash start" instead (new, improved script)
